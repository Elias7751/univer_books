# آلية العمل (System Workflow)

## 1. التسجيل والمصادقة (Registration & Authentication)

- يقوم المستخدمون بالتسجيل عن طريق إدخال بياناتهم واختيار الكلية، القسم، والمستوى الدراسي.
- عند نجاح التسجيل، يتم إصدار رمز (JWT Token) لاستخدامه في الطلبات المصادق عليها.
- يمكن للمدراء (Admins) والمشرفين (Supervisors) إدارة حسابات المستخدمين (مثل حظر المستخدمين أو تغيير صلاحياتهم).

## 2. عملية رفع المستندات والموافقة عليها (Document Upload & Approval)

1. **الرفع (Upload):** يقوم الطالب أو المشرف برفع مستند (ملخص، اختبار، بحث) لمادة معينة.
2. **حالة الانتظار (Pending):** يدخل المستند في حالة `PENDING` ولا يكون مرئياً للمستخدمين العاديين.
3. **المراجعة (Review):** يقوم المدير أو المشرف بمراجعة المستند.
4. **القرار (Decision):**
   - **قبول (Approve):** تتغير حالة المستند إلى `APPROVED` ويصبح مرئياً لجميع المستخدمين في تلك المادة.
   - **رفض (Reject):** تتغير حالة المستند إلى `REJECTED` مع تقديم سبب للرفض.

## 3. تصفح المحتوى (Browsing Content)

- **المحتوى الأكاديمي:** يتنقل المستخدمون عبر (الجامعة -> الكلية -> القسم -> المستوى -> المادة) للعثور على المستندات المعتمدة الخاصة بدراستهم.
- **المكتبة العامة:** يمكن للمستخدمين تصفح الكتب العامة المصنفة حسب المواضيع، بشكل مستقل عن مستواهم الأكاديمي.

## 4. تفاعلات المستخدمين (User Interactions)

- **التقييم (Rating):** يمكن للمستخدمين تقييم المستندات (من 1 إلى 5 نجوم) وترك تعليقات لمساعدة الآخرين في تقييم جودة المحتوى.
- **المفضلة (Favorites):** يمكن للمستخدمين حفظ المستندات في قائمة المفضلة الخاصة بهم للوصول السريع إليها لاحقاً.
- **الإبلاغ (Reporting):** إذا كان المستند غير لائق أو يحتوي على أخطاء، يمكن للمستخدمين تقديم بلاغ. يقوم المدراء بمراجعة هذه البلاغات واتخاذ الإجراء المناسب (مثل حذف المستند).

## 5. الإدارة (Administration)

- يمتلك المدراء لوحة تحكم (Dashboard) تتيح لهم:
  - إدارة الهيكلية الأكاديمية (إضافة/تعديل/حذف الكليات، الأقسام، المستويات، والمواد).
  - مراجعة المستندات المعلقة.
  - التعامل مع بلاغات المستخدمين.
  - عرض سجل النشاطات (Audit Logs) لمراقبة حركة النظام.
